# cocode

認証不要・共有リンクだけで、ユーザーAとユーザーBが「待ち合わせ地点」と「お互いの現在地」をリアルタイムに共有できる、個人開発・低コスト運用前提の位置共有アプリです。

- ユーザーAが待ち合わせ地点(現在地 or 地図タップ)を指定 → 共有リンクが発行される
- ユーザーAとユーザーBは、双方の画面で「待ち合わせ地点」「Aの現在地」「Bの現在地」の3点と、それぞれの現在地から待ち合わせ地点までの徒歩ルートをリアルタイムに確認できる
- セッションは作成から**1時間**、明示的な「終了」操作、またはホストの切断(タブを閉じる等)で即座に失効する。ゲストの切断は10分間の復帰猶予があり、その間に再接続すれば元の参加者として復帰できる(猶予切れ後はそのゲストのみ退出扱いとなり、他の参加者・セッション自体には影響しない)

## 技術スタック

| レイヤ | 技術 | デプロイ先 |
|---|---|---|
| バックエンド | Go (REST + WebSocket) | Cloud Run (`min-instances=0`, `max-instances=1`) |
| フロントエンド | Next.js (静的エクスポート) + MapLibre GL JS | Firebase Hosting 無料枠 |
| データベース | Supabase (Postgres) | Supabase 無料枠 |
| 地図タイル | MapTiler | - |

## アーキテクチャ

```
cocode_project/
  server/   Goバックエンド (REST API + WebSocket)
  web/      Next.jsフロントエンド (静的エクスポート)
```

- フロントエンドはNext.jsの静的エクスポートとしてビルドし、Firebase Hostingで配信する。Goバックエンドとは完全に分離しており、Cloud RunはREST API/WebSocketサーバーとしての役割のみを担う。
- Cloud Runは`max-instances=1`固定。同一セッションのWebSocket接続(A・B双方)が必ず同一インスタンス上に乗るため、Redis等の外部Pub/Subストアを使わずにプロセス内メモリだけでブロードキャストを配信できる。
- セッションの永続データ(トークン・失効時刻・位置情報)のみSupabaseに保存し、DB接続はGoバックエンドからのみ行う(フロントエンドは直接Supabaseを叩かない)。
- セッションの自動削除にCloud Scheduler等は使わず、Goプロセス内の`time.AfterFunc`によるTTLタイマーと、アクセス時の遅延チェックのみで完結させている。
- 待ち合わせ地点までの徒歩ルートはOSRMの公開デモサーバーから都度取得して描画するのみで、サーバー・ブラウザどちらにも永続化しない。
